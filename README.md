# ds-from-app — плагін для Claude Code

Бере живий застосунок за посиланням і з нього будує дизайн-систему та репозиторій-Верстак. Від початку до кінця:

1. **Збирає.** Відкриває застосунок у вашому Google Chrome, знімає екрани й читає з них кольори, відступи, шрифти,
   радіуси, компоненти й переходи. Кожне значення має позначку, як його отримали: виміряно, виведено чи вирішено
   людиною. У застосунку нічого не змінює: форм не надсилає, записи блокує, пароль за вас не вводить.
2. **Показує сторінку для рішень.** Ви обираєте тестовий флоу, перевіряєте назви й відмічаєте, що лише частина
   прототипу (перемикачі ролей, демо-панелі), а не самого продукту.
3. **Будує Верстак.** Токени як змінні CSS, Storybook, опис тестового флоу і сім перевірок (`npm run check` друкує
   десять кроків). Харнес — як у процесі Eleken (eleken-git.github.io/design-process-help/harness): AGENTS.md,
   FRONTEND.md, PROMPT_plan / PROMPT_build, план і журнал прогресу, навички build-page, frontend-qa і client-handoff,
   Stop-хук, що не дає сказати «готово» на червоних перевірках, CI.
4. **Відтворює тестовий флоу** задача за задачею і порівнює із застосунком. Ви бачите обидва поруч, з переліком
   того, що збігається, що ні й чому.

Поки флоу не відтворено, токени вважаються неперевіреними.

## Що потрібно

- Claude Code (у терміналі чи в десктоп-апці).
- Node 22 або новіший, Google Chrome, git.
- Посилання на застосунок. Якщо в нього треба входити — ваш акаунт: входите ви самі, у вікні браузера.

## Встановити (один раз)

```
claude plugin marketplace add DShkiaruk/ds-from-app
claude plugin install ds-from-app@ds-from-app
```

Відкрийте нову сесію Claude Code — команда `/ds-from-app` зʼявиться. Так перевірено в чистому налаштуванні
Claude Code: плагін став прямо з GitHub, його залежності поставились самі, перевірка середовища пройшла.

**Оновити плагін:**

```
claude plugin marketplace update ds-from-app
claude plugin update ds-from-app@ds-from-app
```

Потім нова сесія. Верстак, створений старішою версією, оновлюється окремо: у сесії в теці Верстака скажіть
«онови Верстак до нової версії плагіна». Це один коміт, який ви переглядаєте; ваші правила й тексти не чіпаються.

## Перший запуск

Створіть порожню теку для старту (лише латиницею), відкрийте в ній Claude Code і напишіть:

```
/ds-from-app https://app.example.com
/ds-from-app continue        # продовжити в теці проєкту
```

**Чотири місця, де Claude чекає на вас:**

1. **Підготовка.** Чи треба входити в акаунт, чи є темна тема, де тримати проєкт, чи є в застосунку справжні дані
   людей. Тут же можна одним реченням сказати, який флоу ви хочете відтворити.
2. **Сторінка рішень** (відкривається в браузері). Ви обираєте екрани тестового флоу і їхній порядок, перевіряєте
   запропоновані назви, відмічаєте, що лише прототипне (смуга з перемикачем варіантів, демо-кнопки), і вирішуєте
   про змінні, які застосунок оголошує, але ніде не вживає. Наприкінці — «Готово».
3. **План тестового флоу.** Нова сесія в теці Верстака, фраза «склади план». Claude показує план простими словами й
   чекає вашого «так».
4. **Приймання.** «чи готово?» — застосунок і прототип поруч (`npm run compare` → `extraction/compare.html`), що
   збігається, що ні й чому, чого жодна перевірка не дивиться.

## Робота у Верстаку

Кожна фраза — у новій сесії Claude Code, відкритій у теці Верстака:

| Ви кажете | Що відбувається |
|---|---|
| «склади план» | план задач у `plan/IMPLEMENTATION_PLAN.md`, без коду |
| «зроби наступну задачу» | одна задача на окремій гілці; перевірки мають бути зелені; потім чекає вашого «так» |
| «так, зливай» | задача потрапляє в основну гілку |
| «чи готово?» | усі перевірки і звіт простими словами |
| «готуй передачу» | HANDOFF.md мовою клієнта; комітить лише після вашого «так», нічого не відправляє |

Подивитися результат: `npm run dev` (прототип), `npm run storybook` (компоненти й токени).

Коли значення бракує, Claude не вигадує його і не підбирає схоже: він питає вас, а затверджене записується з вашим
іменем і датою.

## Безпека й дані

- Інструменти лише читають застосунок: запити на запис і з'єднання через сокети заблоковано; форми не
  надсилаються; кнопки на кшталт «Видалити» чи «Вийти» не натискаються.
- Сесії входу й файли `.env` ніколи не потрапляють у репозиторій.
- Нічого не пушиться, не публікується й не відправляється без вашого «так».
- Скриншоти можуть містити дані з застосунку: тримайте Верстак у приватному репозиторії.

## Що не вийде (поки)

- **Сайти із захистом від ботів** (Vercel Security Checkpoint, Cloudflare «Just a moment…»). Такий захист може не
  пустити браузер, яким керує програма: на Vercel це сталося навіть із видимим вікном. Інструмент зупиниться і скаже,
  що робити: власник сайту
  вимикає захист на час роботи або дозволяє ваш комп'ютер, або ви даєте копію файлів застосунку, і її відкриють
  локально. Обходити захист плагін не буде.
- **Стани, яких зйомка не досягла** (натискання, наведення там, де застосунок його не показує, результат після
  введення тексту): інструменти нічого не вводять, тож такі стани позначаються як недосягнуті, а не малюються навмання.
- **Адаптив:** перевіряються лише ширини, на яких знято застосунок; на інших плагін тільки попереджає.

## Скільки це займає

Два холодні прогони, де свіжий Claude мав лише цей плагін, а дизайнер лише відповідав на запитання:

| Флоу | Сесій | Час роботи Claude | Вартість (за цінами API) |
|---|---|---|---|
| 2 екрани | 10 | близько 44 хв | близько $5 |
| 4 екрани, від списку до панелі | 13 | близько 85 хв | близько $10 |

Плюс час на ваші відповіді. Обидва прогони довели свої флоу до `npm run check` 10 з 10; що вони знайшли і що
виправлено — у [CHANGES.md](CHANGES.md).

## Якщо щось не так

Опишіть, що сталося, в [issues](https://github.com/DShkiaruk/ds-from-app/issues): посилання на застосунок (якщо
можна), що ви сказали Claude і що він відповів.

## Для того, хто змінює плагін

`npm test` — швидкі перевірки; `npm run selftest` — інструменти проти синтетичних застосунків із відомою відповіддю
(кілька хвилин, відкриває браузер); `npm run selftest:workbench` — Верстак від початку до кінця, кожна перевірка
червоніє на закладеному дефекті. `DSFA_KEEP_WORKBENCH=<тека> npm run selftest:workbench` зберігає цей Верстак, щоб
прогнати його CI на GitHub.
