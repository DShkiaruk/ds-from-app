# Stories

- Folder and file names are ASCII: a screen folder in kebab-case (`src/screens/overview/`), a component in
  PascalCase. Storybook's test runner finds no tests in a story under a non-ASCII path (gate 5 fails on one). The key in
  `src/screens/index.ts` stays the captured screen name (`'огляд': Overview`), so the route `#/огляд` and parity still
  match.
- Title (gate 5 checks the prefix): `Components/<Name>` for a component in src/components, `Screens/<screen folder>` for a screen,
  `Screens/<screen folder>/<Name>` for a component only that screen uses; Foundations (Overview, colours by what they paint, text styles, scales) are generated by tokens-css from the
  extraction; never edit them.
- Docs: every component has a Docs page (autodocs) built from its JSDoc — a one-line comment on the component (what it is, where the app
  uses it) and on each prop. Screens and Foundations have none.
- A component's stories: `Default` (args for every prop, so Controls work), one per variant the app shows, and
  `States` — drawn with `StateGrid` (src/foundations/StateGrid.tsx), every state with its name under it (default, hover,
  focus-visible, active (pressed), disabled, the app's own) and `parameters: { pseudo: pseudoStates() }`; a wrapper with the `id`
  `hover` / `focus-visible` / `active` gets the pseudo state on its inner element. Only states the component's CSS styles and the app
  shows; a state no capture reached is listed without a `node` and shows "not reached (NEEDS-STATE)" — never an invented look.
- Layout around examples in a story may use inline styles; the component itself may not.
- Every story must pass the accessibility test (`npm run test:stories`): a control without a name fails it.
- When a story fails the accessibility test because the APP itself does it (its colours fail contrast, which parity requires to match), exclude only the element the app fails on, so the rest of the story stays checked: `parameters: { a11y: { config: { rules: [{ id: '<rule id>', selector: '*:not(<selector of that element>)' }] } } }` (that rule skips only that element; its other rules still run), or `parameters: { a11y: { context: { exclude: [['<selector of that element>']] } } }` (every rule skips it), with the comment `// the app itself: <what> — reported to the designer`; also write `APP-A11Y: <story>, <rule>, <what>` in plan/progress.md. Turn a rule off for the whole story (`parameters: { a11y: { config: { rules: [{ id: '<rule id>', enabled: false }] } } }`, same comment, same progress line) only when no element selector can single it out. Never turn the test off globally.
- A screen's story renders the screen component; its data is the screen's own invented data.
