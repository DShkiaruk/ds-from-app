# Верстак

Тут дизайн-система застосунку, яку інструмент ds-from-app зняв із живого застосунку, і прототип на ній.

Відкрийте Claude Code саме в цій теці (нова сесія тут; на запит дозвольте довіряти теці) і скажіть «склади план»:
правила, перевірки й навички цього репозиторію вантажаться лише в сесії, що почалась у ньому.

## Відкрити

```
npm install
npm run dev          # прототип: http://localhost:5173
npm run storybook    # компоненти й токени: http://localhost:6006
```

## Як працювати з Claude

1. «Склади план» — Claude читає PROMPT_plan.md і пише plan/IMPLEMENTATION_PLAN.md. Ви читаєте й кажете «ок».
2. «Зроби наступну задачу» — Claude бере одну задачу (PROMPT_build.md), робить її, проганяє перевірки, зберігає зміни в git. Одна задача — одна нова сесія (правило 10 в AGENTS.md).
3. Дивіться результат: прототип, Storybook і `npm run compare` — застосунок і прототип поруч (extraction/compare.html).

## Перевірки

`npm run check` — сім перевірок (команда друкує десять кроків): код, лише токени у стилях, типи, шар токенів, історії в Storybook, збірка й доступність,
схожість із застосунком. Поки хоч одна не пройшла, робота не готова. Коли все добре, кожна показує ✓.

Перевірка схожості із застосунком (`npm run parity`) працює локально, на тому комп'ютері, де знято застосунок: на Linux у CI шрифти інші, тож CI запускає `npm run check:ci` — ті самі перевірки без схожості.

## Де що лежить

- `extraction/` — що знято із застосунку: знімки екранів, токени, ваші рішення. Руками не правимо — крім `extraction/canon/decided.tokens.json`, і то через агента (правило 4 в AGENTS.md).
- `src/tokens/` — токени як змінні CSS. Згенеровано, руками не правимо.
- `src/components/`, `src/screens/` — компоненти й екрани.
- `src/tokens` (Storybook → Foundations) — які токени є; `DESIGN.md` — їхній знімок на момент створення; `PROJECT.md` — звідки все; `specs/pages/` — опис тестового флоу.

Публікація (GitHub, Vercel) — лише після вашого «так»: знімки екранів можуть містити дані реальних людей.
